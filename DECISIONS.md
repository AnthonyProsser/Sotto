# Sotto — Decisions log

**Newest first. Append, never rewrite.**

## How this file works

`docs/` holds read-only copies of the spec, the build order, and the token sheet. The originals live in `/Users/anthonyprosser/Documents/Sotto/`. Nothing in `docs/` is ever edited here — see `CLAUDE.md` §0.

Decisions get made during build sessions, because a spec that survives contact with Swift unchanged was not a spec. When one happens:

1. **Claude Code appends an entry below** — newest at the top of the table, using the template.
2. **Claude Code says so in its reply**, naming the spec section it contradicts if there is one. A decision logged silently is a decision nobody folds back.
3. **Anthony folds the entry into the real spec** in `Documents/Sotto`, then re-syncs `docs/` with the `cp` line in `docs/README.md`.
4. **Anthony flips the last column to Yes** and notes the resulting spec version.

Until step 4, the copies in `docs/` are out of date on that point. That is fine as long as everyone knows it — which is what this file is for. **A `No` in the last column means the spec copy is wrong about that thing right now.**

**What belongs here:** anything that contradicts, extends, or resolves the spec. A new tier-2 token row. A constant that turned out wrong in practice. A rule that could not be implemented as written. An open issue from §12 that got settled. A number that was a placeholder and is now real.

**What does not:** ordinary implementation choices the spec does not speak to. Naming a Swift type, splitting a file, picking a collection type. If the spec has no opinion, neither does this file.

| 2026-08-15 | 2 | **Right Cmd is a live modifier for the first 250 ms of a hold and is consumed after it. Past the 250 ms line the gesture owns the keyboard: Right Cmd stops acting as a modifier and every non-modifier keydown is swallowed, Escape alone excepted.** Normal behaviour returns on release, while transcription runs. **A chord under 250 ms disarms**, exactly as Escape does — the speculative capture is discarded, the chord passes through and copies, releasing the key afterwards does nothing, and the key never becomes consumed for that hold. **Latched is unaffected**: no key is held, so Cmd chords work normally throughout a latched recording. | Anthony: *"If I am holding the right command and I am recording, I shouldn't be able to copy and stuff during that… during that time right command is only for recording… Nothing else should happen until I let go."* The spec's unqualified **never consumed** was protecting exactly one case — Right-Cmd+C keeps copying — and **that case survives intact**, because a chord is pressed inside the 250 ms window in practice. What changes is the tail, where the key has already been classified as a gesture and letting it also act as a modifier is one physical key doing two jobs with no way for the user to say which. **The full swallow beat the two narrower options on a mechanical fact, not on taste:** CGEvent flags are computed from hardware state, so suppressing the modifier's `flagsChanged` does not strip Cmd from the keydowns that follow — stripping it converts Cmd+C into a literal `c` typed into the document the user is about to dictate into, which is silent corruption of the insertion target. **The cost, stated and accepted:** left-hand shortcuts die for the length of a hold too, Cmd+Tab and Cmd+S included, because the swallow keys off keydowns rather than off which modifier is down.
