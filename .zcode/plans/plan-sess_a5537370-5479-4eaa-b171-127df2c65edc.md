# Slice 10 — Chat in the main window, generation on both surfaces

**Basis:** build order slice 10; spec §10.2, §5.3, §14.3; the gap-1 decision (turn anatomy is the SVG's, verbatim — already built in the overlay's `ConversationView`). Today's three rulings extend the build order and get `DECISIONS.md` rows: (1) generation wires into **both** the main window and the overlay's docked panel (supersedes the slice's "main window only" build line and extends the 2026-09-01 "generation stays a later stage" row); (2) a composer in the main window detail; (3) chat Delete…/Reveal in Finder mirroring the Audio sidebar.

## What exists and is reused (no rebuilds)

- **Turn anatomy**: `Views/ConversationView.swift` — `Turn`/`Source`, `turnView` (YOU/SOTTO labels, 2 pt accent rule, no bubbles), `turn(from:)` selection-fence/image parse. Extended, not copied.
- **Sidebar twins**: `AudioLibrary` / `AudioSidebar` / `RecordingRow` / `FailureBanner` in `Views/AudioWorkspace.swift` + `History/AudioLibrary.swift` — pinned-first ordering, search, pin glyph, context menu, empty states.
- **Engine (slice 7, never called from app code)**: `ChatEngine.createSession`, `ChatSession.sendMessage` (streams, persists, raises `Activity.generating`), `ChatHarness`, `ChatSerializer.deserialize` (full reader already exists and is round-trip tested).
- **Shell stubs**: `MainWindowView.modeList` `case .chat: List {}`, `detail` `case .chat: ContentUnavailableView`, `chatSearch` binding — all waiting for this slice.
- **Composer pieces**: `ComposerField` (IME-safe Return-sends), `OverlayView`'s add-context menu, send button, `WrapLayout`.

## Build steps

**1. Chat pin flag — `ChatSerializer` extension.** Frontmatter gains `pinned:` (write + parse). Spec §9.1 names the flag; the format has never carried it. Row in DECISIONS.md.

**2. `ChatLibrary`** (new, `History/ChatLibrary.swift`, mirrors `AudioLibrary`): `@MainActor @Observable` over `ChatFolder.root` — chats with id/slug/title/updated/pinned/snippet; `visible` = pinned first, then newest-first (§10.2); search over title + message text bound to the already-reserved `MainWindowState.chatSearch`; `togglePin`, `delete` (removes folder), Reveal in Finder; posts `.chatsDidChange` (beside `.audioHistoryDidChange`) so window sidebar, overlay picker, and docked panel stay in sync. `DraftStore.recentChats` migrates to this layer and its duplicate folder-walker is deleted in the same commit (§0.3).

**3. Live conversation layer** (new `Chat/ChatConversation.swift`): one `@MainActor @Observable` per open chat, owned by `ChatEngine`-keyed session so **both surfaces subscribe to the same truth** and `ChatSession` (actor) is the single writer to `chat.md` — this also removes the two-writer hazard where `DraftStore.send`'s direct read-modify-write could clobber an in-flight session. Holds renderable turns, streaming text, `isGenerating`, `failure`. Adds ChatSession hydration from deserialized `ChatSessionState` (serializer round-trip already tested). `send` resolves the model (`ChatModelID` default, `apple-foundation` fallback — existing convention), drains the stream: `.token` appends to the live turn, errors attach to the turn, cancel keeps partial text. One generation per chat at a time; the send control becomes stop while generating (§5.8).

**4. Main window chat UI** (new `Views/ChatWorkspace.swift`): `ChatSidebar` — enabled New Chat button in the top slot (mirrors Audio's disabled Transcribe File stub), list rows (title, date, pin glyph), context menu Pin/Unpin · Delete… behind confirmation · Reveal in Finder, empty states for no chats and no search results. `ChatDetail` — header (title, date, pin button), the conversation, composer at the bottom reusing `ComposerField` + the overlay's composer controls (+ attach menu, send/stop).

**5. Failures (§14.3, nothing modal).** Model unavailable / model load failure → banner at the top of the chat surface (the `FailureBanner` pattern) naming the reason. Generation / tool-call failure → rendered inline in the conversation, attached to the turn that failed. Wording lives with the feature, not a central vocabulary.

**6. Overlay generation.** `OverlayView.send()` routes through the same `ChatConversation` layer (persist + generate) instead of `DraftStore.send`'s direct write. The docked panel's `ConversationView` renders from the live session when one exists for its slug (streaming included), disk read otherwise; the bare bar's send still commits and closes — the reply streams into the chat and is visible wherever the conversation is next opened. Send control shows stop while that chat generates.

**7. Escape / stop wiring.** Observe the orphaned `.sottoCancelGeneration` notification (posted by the Esc stack's priority 3, observed by nothing today) and cancel the active send task(s). Extend the Esc remainder so priority 3 (stop generation) fires while Sotto is frontmost with the main window up and the overlay down — §10.4's stack is app-UI-scoped; the 2026-09-02 mechanics row gets a superseding note in DECISIONS.md.

**8. Engine startup wiring.** Call `ChatEngine.shared.registerLocalModels(in: ModelStore.root)` at launch so installed MLX models can back a chat; `.generating`/`.modelLoading` Activity contributors already exist and need nothing new.

**9. Tests** (headless, extending `ChatEngineTests`): serializer pin round-trip; library ordering/search/delete; hydration → continue an old chat; send → streamed reply with per-turn model attribution; cancel keeps partial text.

**10. Verification.** Build with `DEVELOPER_DIR` per `rules/design.md` §8.2; run the §14 grep (standard-window scale: §14.1/14.2/14.5 + screenshots of default, empty, and failure states); screenshot the docked panel streaming. **Leave Sotto running** (§0.8).

**11. Records.** DECISIONS.md rows for the four extensions above; `rules/slices.md` §5 gains the slice-10 amendments pointing at those rows (build order is read-only).

## Local choices I'll make without asking (one line each)

- Attribution form: the turn's model name appended to the SOTTO caption label in secondary text — the only label the anatomy has.
- Streaming appearance: text fills the assistant turn as it arrives, a secondary ellipsis until the first token, no spinner.
- Chat row mirrors `RecordingRow`; detail header mirrors `AudioDetail`.
- New chats persist on first send, so the folder appears in the sidebar only once it exists.
- `.tool` messages stay unrendered — no tools exist until slice 12 designs tool blocks; the failure treatment covers the seam.
